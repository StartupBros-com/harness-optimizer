# Harness Optimizer v0.2.0

## Highlights

- Investigate recurring problems across six areas of your Claude Code setup before choosing repairs.
- Have separate agents challenge the diagnosis, proposed changes and reported outcome for a batch of up to three repair families.
- Keep missing evidence and approval requirements visible. A lower warning count is not an improvement if checks disappeared.

## First public release

Run `/harness-optimizer:harness-optimizer` in the project you want to investigate.
You can narrow the scope to tooling friction, instructions, memory or another
supported evidence lane. Missing optional specialists do not prevent ordinary
repository repairs, and the optimizer does not install them for you.

This release packages the existing multi-lane implementation for the `hov`
marketplace. It adds public installation guidance and offline CI without changing
the skill or agent instructions. There are no hooks, background schedules or
automatic optimization runs.

## Limits

The package and native agent declarations target Claude Code. Other runtimes and
live specialist interoperability remain unverified. The included offline tests
check contracts and graders; they do not prove field benefit. Investigators and
reviewers consume model tokens, and prompt-defined attempt limits are not hard
spending caps. Existing permissions and specialist-specific consent still apply.
